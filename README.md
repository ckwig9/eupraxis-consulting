# Eupraxis Consulting website

Static site: `index.html` (landing page, 9 sections per scope), `blog.html` (blog index), `blog/*.html` (posts, generated), `privacy.html`, `terms.html`.
No build step. Open `index.html` or serve the folder.

## Structure
- `css/style.css` – all styles. Brand tokens at the top (`:root`). Swap colors/fonts here when Craig's brand spec arrives.
- `js/main.js` – nav, reveal animations, whiteboard draw-on, contact modal, GHL submission, blog filters.
- `assets/brand/` – headshot, logo (white PNG from old site, SVG favicon; the nav logo is an inline SVG mark + wordmark).
- `assets/clients/` – client logos from the old site (credibility strip).

## GoHighLevel
Set `GHL_WEBHOOK_URL` in `js/main.js` to an Inbound Webhook trigger URL. The workflow should:
create/update contact, add tag `website-inbound`, add to the **Inbound** pipeline, notify Craig.
Fields posted as JSON: `name, email, phone, message, topic, page, submitted_at`.

## Blog (posts live on this site)
Posts are Markdown files in `posts/`. A small script turns them into pages.

- `posts/<slug>.md` – one file per post. The file name becomes the URL: `blog/<slug>.html`.
- `templates/post.html` – the post page layout. Header and footer are pulled from `blog.html` at build time.
- `blog/` – generated post pages. Do not edit by hand; they are overwritten on every build.
- `assets/blog/` – post images.
- `feed.xml`, `_redirects`, `.htaccess` – generated on every build.

### Publish a post
1. Create `posts/my-new-post.md`:
   ```
   ---
   title: The title of the post
   date: 2026-02-09
   category: run-outgrow
   description: One or two sentences shown in the list and in search results.
   image: assets/blog/my-image.png
   ---
   Body in Markdown. **Bold**, *italic*, ## headings, - lists, and ![alt](assets/blog/pic.png) images all work.
   ```
   `category` must be one of: `run-outgrow`, `culture`, `proactive`, `outgrow-system`.
   Optional keys: `series` (e.g. `CEO series, part 6`), `image_alt`, `draft: true` (hides the post).
2. Run `python scripts/build_blog.py` from the project folder (needs `pip install markdown` once).
3. Upload the whole folder. The build updates `blog/`, the list on `blog.html`, the latest three on
   `index.html`, `feed.xml`, and the redirect files.

The 21 posts from the old WordPress site were migrated with `scripts/migrate_wp.py` (kept for reference;
not part of the build). Their bodies are stored as HTML with `format: html` in the front matter.

## Redirects
`_redirects` (Netlify/Cloudflare Pages) and `.htaccess` (Apache/cPanel) are generated by the blog build. They send every
old WordPress post URL (`/slug/`) and the old feed to the new pages. Keep whichever file the host uses.
